# rvsd-v1-vectors.json

Known-answer vectors for the RVF Stream Descriptor (ADR-353). Two independent
implementations (`rvf-wire`, `rvm-rvf`) must produce and consume these exact
bytes. The file is generated by `rvf-wire/tests/stream_vectors.rs`; that test
fails if the committed file differs from a fresh deterministic run. Rewrite it
with `RVSD_REGEN=1 cargo test -p rvf-wire --test stream_vectors`.
All integers in the formats are little-endian; all `*_hex` values are lowercase hex.

## Top level

| Key | Meaning |
| --- | --- |
| `test_only_key` | `seed_hex` is an Ed25519 seed used only for these vectors (never a real key). `other_seed_hex` is a second test key. |
| `file_id_hex`, `other_file_id_hex` | 16-byte file ids of the main and the "other" file. |
| `body` | The unchanged RVF body (`hex`), its `sha256_hex`, and `segments` (id, type, offset, stored length; the last entry is the 4096-byte root page pseudo-entry, type 254). |
| `other_body_hex` | Body of the other file (differs only in segment 5). |
| `stages_by_segment_order` | Stage per segment in body order, used by the `*-stage` streams. |
| `streams` | Four positive streams: `m1-file`, `m1-stage` (`chunk_log2` 255, one chunk per segment) and `m2-file`, `m2-stage` (`chunk_log2` 12, 4 KiB chunks). `*-stage` streams set `requires_mask` to all lower stages and deliver frames in `(stage, body order)`. |
| `positive_variants` | Positive cases built by editing a stream (see `edits`). |
| `negative` | Cases that must be refused. |

## Streams

`descriptor_hex` is the complete signed descriptor; `descriptor_hash_hex` its SHA-256.
`entries[i]` lists the table entry fields plus the recomputed `leaf_hashes_hex`
(one per chunk) and `chunk_table_hash_hex`: the leaf itself when `chunk_count` is 1,
otherwise the chunk-list hash. `frames[i].hex` is the exact frame (type byte
included) and `frames[i].expect` the event a verifier with the default policy
(`fault_budget` 4, trusted key = test key) must produce for it:
`DescriptorVerified`, `TableVerified`, `Chunk` (with `segment_verified`,
`stage_verified`, and `complete` = `Verified`, `Unverifiable` or null) or `Error`.
`final_state` is the verifier state after the last frame.

## Frames

* `00 | len u32 | descriptor` &nbsp;(descriptor)
* `01 | seg_id u64 | chunk_index u32 | len u32 | bytes` &nbsp;(chunk)
* `02 | seg_id u64 | n u32 | n * 32-byte leaves` &nbsp;(chunk table; only for segments with more than one chunk, sent before their first chunk)

## Hashes and signature

* Leaf: `SHA-256(0x00 | file_id | seg_id u64 | chunk_index u32 | chunk_len u64 | bytes)`. Note `chunk_len` is u64 in the hash and u32 in the frame.
* Chunk list: `SHA-256(0x01 | file_id | seg_id u64 | n u32 | leaf_0 | ... )`.
* Signed message: the ASCII bytes `RVF-v1-stream-descriptor` followed by one NUL byte, then **every descriptor byte before the 64-byte signature, including the 2-byte `sig_len` field**. Ed25519, verified with `verify_strict`.
* `signer_key_id` = first 8 bytes of SHA-256(public key). Magic is the raw bytes `52 56 53 44` ("RVSD").
* A descriptor is exactly `0x90 + 72 * seg_count + 2 + 64` bytes; any other length is refused.

## Descriptor decode order (reported reason = first failure)

1. length > `max_descriptor_bytes` (1 MiB) -> `StreamLimitExceeded`; fixed header: magic, version, flags, algorithms, `chunk_log2`, reserved bytes, `table_len == 72 * seg_count`;
2. `seg_count > max_segments` (16384) -> `StreamLimitExceeded`; exact total length -> `StreamDescriptorTruncated`; `sig_len == 64`;
3. signer lookup by `signer_key_id` in the trust set (`UnknownSigner`), signature (`StreamBadSignature`);
4. expiry on a trusted clock (`StreamExpired`), expected `policy_hash` (`StreamPolicyMismatch`), epoch pin (`StreamStaleEpoch`, or `StreamEpochConflict` at an equal epoch with a different descriptor hash);
5. table: at least one entry, entries start at 0 and are contiguous, end at `body_len`, unique `seg_id`, `stored_len >= 64` (root page: any non-zero, must be last), `stage < 32`, a segment never requires its own stage, stage requirements are acyclic (`StreamTableInvalid`); size caps (`StreamLimitExceeded`).

## Negative cases

Each entry in `negative` names a base `stream`, a `policy` (trust set, `fault_budget`, `epoch_pin`, `now_ns`; all other limits default), and `edits` applied in order to the base frame list:
`xor {frame, offset, mask}` (offsets are into the frame bytes), `drop {frame}`, `dup {frame}` (insert a copy after), `swap {a, b}`, `keep_first {count}`, `insert {at, hex}`, `replace {frame, hex}`, `cut_tail_bytes {frame, bytes}`.
`expect` gives the `first_error_frame` index, `reason` and `code` (the error code of the first refused frame), the `final_state` (`Rejected:<reason>`, `Poisoned:<reason>`, `Receiving`), and how many chunks and bytes were released. Every frame after a poisoning must be refused with `StreamPoisoned` (0x0817) and release nothing.

## Rules the vectors rely on (clarifications of ADR-353)

* Frames of a size that contradicts the signed descriptor, a chunk table whose `n` is wrong, and a frame shorter than its own header poison the stream at once (`StreamFrameSizeLie`). Duplicate, out-of-order, unknown-segment, unknown-type and chunk-before-table frames are counted faults (`StreamUnexpectedFrame`); a leaf or table hash mismatch is a counted fault; a chunk whose `requires_mask` stages are not fully verified is a counted fault (`StreamRequirementsUnmet`). The stream is poisoned when the fault count exceeds `fault_budget`. A refused frame never advances the expected chunk.
* `rvf_identity` must be all zero when `identity_present` is clear.
* The running identity SHA-256 is fed only while chunks arrive contiguously in file order. Otherwise `complete` is `Unverifiable` (the consumer may re-read its persisted body and compare).
* Error codes are `rvf-types` `ErrorCode` values `0x0805..=0x0819` plus the existing `UnknownSigner` 0x0802; see `rvf-types/src/error.rs`.
